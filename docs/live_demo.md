# Gate 11 Live Provider Demo

Gate 11 connects the existing authorized intervention to provider boundaries. The deterministic decision engine remains the only action selector; this gate does not recompute decisions.

## Modes and configuration

Every operation is labelled `LOCAL`, `MOCK`, `TEST`, or `LIVE` and the value is persisted on provider records/events. `LOCAL` uses deterministic in-process providers. `MOCK` is reserved for injected test doubles. `TEST` and `LIVE` require explicit provider configuration and are never implied by a local provider.

Server-side variables are listed in `.env.example`:

- Razorpay: `PAYMENT_PROVIDER=razorpay`, `PAYMENT_MODE=TEST` (or `LIVE`), `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `RAZORPAY_WEBHOOK_SECRET`. Recovery payment links request Razorpay-native SMS/email notification when the corresponding customer contact is present.
- Optional Twilio WhatsApp: `MESSAGING_PROVIDER=twilio`, `MESSAGING_CHANNEL=whatsapp`, `MESSAGING_MODE=TEST`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_FROM_NUMBER`, `TWILIO_WHATSAPP_TO_NUMBER`, and `TWILIO_WHATSAPP_CONTENT_SID`. It is not used for Razorpay payment-link delivery.
- Optional voice HTTP adapter: `VOICE_PROVIDER=live`, `VOICE_MODE=TEST` (or `LIVE`), `VOICE_ENABLED=true`, `VOICE_BASE_URL`, `VOICE_API_KEY`, `VOICE_AGENT_ID`, and `VOICE_PHONE_NUMBER`.
- Exotel trial voice: `VOICE_PROVIDER=exotel`, `VOICE_MODE=TEST`, `VOICE_ENABLED=true`, `VOICE_PUBLIC_BASE_URL`, `EXOTEL_API_KEY`, `EXOTEL_API_TOKEN`, `EXOTEL_ACCOUNT_SID`, `EXOTEL_APP_ID`, `EXOTEL_CALLER_ID`, and optionally `EXOTEL_WEBHOOK_SECRET`. CHIMERA derives the Exotel flow URL from the account SID and app ID using Exotel's `start_voice` flow URL; the webhook token is optional and generated by the operator, not Exotel. Exotel trial calls must target a verified account user until KYC approval.
- For a real Hinglish conversation through an Exotel Flow Voicebot applet, set `EXOTEL_AGENTSTREAM_ENABLED=false`, `EXOTEL_STREAM_URL=wss://<public-host>/api/v1/voice/exotel/stream`, `SARVAM_ENABLED=true`, and `SARVAM_API_KEY`. In the published Flow's Voicebot applet, use the HTTPS resolver `https://<public-host>/api/v1/voice/exotel/stream-resolver`; CHIMERA returns the per-call WSS URL. The bridge receives Exotel's 8 kHz raw PCM bidirectional stream, resamples caller audio to 16 kHz for Sarvam Saaras `codemix`, and returns Sarvam Bulbul `linear16` audio as 8 kHz raw PCM. Direct AgentStream call creation remains available with `EXOTEL_AGENTSTREAM_ENABLED=true`.
- For a browser-only voice presentation, set `SARVAM_API_KEY`, `SARVAM_ENABLED=true`, `PIPECAT_SARVAM_LLM_MODEL=sarvam-105b`, and `PIPECAT_ALLOWED_ORIGINS` for the frontend origin (include `http://localhost:3003` for this demo). Set `NEXT_PUBLIC_API_WS_BASE_URL` to the browser-reachable backend WebSocket base (`ws://localhost:8000/api/v1` locally, or `wss://<api-host>/api/v1` over HTTPS). Run **Demo Scenarios → Voice-Assisted Recovery** and start the **Talk through the abandoned payment** panel. This uses Pipecat's FastAPI WebSocket transport with Sarvam Saaras/Bulbul and is read-only: it does not create payment links or mutate recovery state. The setup no longer requires the configured phone provider to be local; Exotel/Twilio can remain configured for separate telephony work.

Credentials stay on the server. Provider adapters bound timeouts, verify webhook signatures, retain only sanitized payloads/hashes, and deduplicate provider event IDs.

## Demo workflow

Run the API locally with the repository runtime, then submit observable-only case data:

```powershell
& "C:\Users\sahil\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" -m backend.scripts.run_live_demo
```

The script calls `POST /api/v1/demo/recovery`, which creates the case, invokes the existing deterministic decision, authorizes the intervention, and routes the stored action. Inspect the result with `GET /api/v1/recovery-cases/{case_id}/journey`. A local link becomes `RECOVERED` only after a valid signed local payment event; message delivery, retry acceptance, and voice agreement remain non-payment outcomes.

For Razorpay, configure `/api/v1/payments/webhook/razorpay`. For Twilio
WhatsApp, use `/api/v1/messaging/webhook/twilio`; for Twilio voice, use the generated
`/api/v1/voice/twilio/status` and `/api/v1/voice/twilio/twiml` callbacks. Use
provider test credentials and a test customer only. If credentials are absent,
report the run as `LOCAL`; never label it live.
For Exotel voice, CHIMERA sends the outbound request using the configured flow
and receives status callbacks at `/api/v1/voice/exotel/status`. For the Flow
Voicebot path, the Flow must be published and the Voicebot applet must point at
the HTTPS resolver above. Use a verified trial customer only.

Scenarios A–E are reproducible by submitting cases with the corresponding observable failure context and following the stored selected action. The journey endpoint exposes detection, diagnosis, intervention, provider records, outcomes, and a deterministic chronological audit stream.

## Browser voice demo flow

```text
Persisted VOICE_RECOVERY intervention
          │
          ▼
Browser PipecatClient ── protobuf WebSocket audio ──► FastAPI Pipecat transport
          ▲                                             │
          │                                             ├─ Sarvam Saaras v3 STT
          │                                             ├─ grounded Sarvam LLM
          │                                             └─ Sarvam Bulbul v3 TTS
          │                                             │
          └────────────── streamed response audio ◄────┘
```

The case facts are injected server-side from the intervention's `VoiceContext`: amount, currency, failure reason, payment method, and incident signal. The model receives no payment credentials or hidden ML features. It is instructed to explain the failure, answer in concise Hinglish, and route any request for a payment link back to the secure test checkout/operator workflow. The browser transcript is presentation-only; the existing persisted Exotel/Twilio call history remains the source of truth for telephony conversations.
